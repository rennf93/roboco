# RoboCo vs. GitHub Copilot Coding Agent's Baked-In Review + Security Scanning

GitHub Copilot coding agent advertises free, baked-in self-review and security scanning (CodeQL) on every agent-authored pull request, included at no extra cost as part of the Copilot subscription — positioning automated review and vulnerability scanning as a default, not an add-on, for agent-generated code.

Source: [GitHub Copilot coding agent documentation](https://docs.github.com/en/copilot/how-tos/use-copilot-agents/coding-agent)

**Response decision:** no product change is warranted. RoboCo already runs a dedicated, gated security scan on every task before it can pass, and RoboCo's review is not a single self-review pass at all — it is an independent multi-stage chain (PR-reviewer gate, then QA, then CEO approval) that is stricter than a same-agent self-review step. This note records RoboCo's verified posture against that framing, checked directly against this codebase rather than assumed.

## Verified facts

1. **Security scanning runs unconditionally inside the merge gate, not as an opt-in extra.** `make bandit` (`Makefile:221-226`) runs `uv run bandit -r roboco -ll` as its own standalone target, and separately `make quality` (`Makefile:286`, the full merge gate every task is held to) runs its own inline `uv run bandit -r roboco/ -ll` call at `Makefile:305-306` — a step in `quality`'s own recipe, not a dependency on the standalone `bandit`/`security` targets — so every task's quality gate includes a real static-security scan before submission, the same "free, baked-in" default posture Copilot advertises, run from source rather than a hosted add-on.
2. **Review is not a single self-review pass — it is an independent PR-reviewer gate.** A dedicated `pr_reviewer` role owns `pr_pass`/`pr_fail` on the assembled diff (`roboco/services/gateway/choreographer/pr_gate.py:157-219`); the lifecycle spec restricts both transitions to `Role.PR_REVIEWER` only (`roboco/foundation/policy/lifecycle.py:597-616`, `AWAITING_PR_REVIEW -> AWAITING_PM_REVIEW` / `-> NEEDS_REVISION`) — a different agent than the one that authored the code, not the author reviewing itself.
3. **That PR-reviewer gate sits on top of an independent QA pass.** `qa_pass`/`qa_fail` are restricted to QA roles (`roboco/foundation/policy/lifecycle.py:545-559`, `_QA_ROLES`, `AWAITING_QA -> AWAITING_DOCUMENTATION` / `-> NEEDS_REVISION`) and run as a separate lifecycle stage before the PR-reviewer gate's target (`AWAITING_PM_REVIEW`) is ever reached — a second independent reviewer, not a second pass by the same agent.
4. **Both layers sit beneath a CEO-approval gate before anything reaches master.** `AWAITING_CEO_APPROVAL -> COMPLETED` (`ceo_approve`) is restricted to `frozenset({Role.CEO})` (`roboco/foundation/policy/lifecycle.py:666-675`), and every CEO-only route delegates to the single shared check `require_ceo_role()` (`roboco/api/deps.py:627-639`) — a human sign-off is the final gate, not just automated review.
5. **RoboCo's differentiated posture.** Copilot's advertised capability is a single self-review + security-scan pass by the same agent, bundled free with the subscription. RoboCo matches the "free, baked-in, gated" security-scan claim (`make quality`'s own inline bandit call, `Makefile:305-306`, runs on every task) and goes further on review: RoboCo's chain is three independently-role-checked stages — PR reviewer, then QA, then the CEO — none of which is the authoring agent, versus Copilot's one same-agent self-review step.
